# 来源登记与语料规范

## 候选来源

以下只是待核实的入口，尚未联网检查页面、许可或版本，也尚未抓取内容。公开可访问不等于允许重新分发；代码许可也不自动覆盖所有文档和第三方材料。

| 来源 | 拟收集内容 | 开始前需要核实 |
| --- | --- | --- |
| Open CASCADE Technology 官方文档 | 几何表示、B 样条曲面、拓扑、容差、有效性和形状修复 | 精确版本、文档许可、API 页面来源位置 |
| PythonOCC 官方仓库和文档 | OCCT 的 Python 接口与许可允许的示例 | pythonocc 与 OCCT 版本对应、示例许可 |
| Analysis Situs 官方资料 | 曲面分析、诊断、逆向工程相关说明 | 站点/仓库真实性、具体文档许可与引用条件 |
| 允许使用的课程材料和作者开放论文 | NURBS、连续性、拟合及领域检索方法 | 授权范围、作者和版本；无授权则仅作书目引用 |
| 自行记录的典型问题 | 症状、输入条件、错误、检查和处理结果 | 去除敏感数据；注明真实记录或合成场景 |

方法综述检索线索：Robertson 与 Zaragoza 的 BM25 综述、Reimers 与 Gurevych 的 Sentence-BERT、Lewis 等人的 RAG 工作，以及查询扩展和本体增强检索文献。NURBS 理论可从 Piegl 与 Tiller 的相关著作追溯。这里不是已审核参考文献表，正式引用前须核对题名、年份、版本和可访问来源；不得直接将有版权的整本书导入语料。

## 来源记录字段

`source_id`、`title`、`publisher`、`canonical_url`、`retrieved_at`、`language`、`product_version`、`license_name`、`license_url`、`permission_status`、`permitted_use`、`local_path`、`content_sha256`、`notes`。

`permission_status` 取 `pending`、`approved`、`excluded`；`approved` 需记录许可或授权依据以及允许的使用范围。待核实来源先登记，暂不进入正式索引。对只允许本地研究使用的内容，不打包公开发布。访问日期必须使用实际取得资料的日期。

## 片段字段与切分

每个片段至少包含：`chunk_id`、`source_id`、`section_title`、`locator`、`text`、`language`、`product_version`、`content_sha256`。`locator` 应能定位到页面锚点、章节、页码或行号。片段继承来源的许可状态。

先按标题、API 条目、段落和代码块切分，保持定义与必要上下文完整；过长内容再按所选嵌入模型的 tokenizer 分块。初始长度可在约 250–500 token、重叠 40–80 token 范围内通过开发集检查后固定，不按字符数假装成 token 数。

去掉导航、重复页脚和无意义菜单；保留 API 大小写、代码符号、数学条件和版本限制。对原文进行规范化后计算哈希，避免网页镜像或重复抓取产生多个相同证据。保持原始下载与清洗版本的映射。

## 质量关卡

1. 来源、许可处理、版本和定位字段齐全。
2. 随机检查至少 10% 的片段，且每个来源至少检查一个；确认无断句导致的条件丢失、代码破坏或定位错误。
3. 记录五类问题的覆盖情况，不为凑数量复制相似页面。
4. 诊断关系必须有证据片段和适用条件，不能把论坛猜测或模型生成内容直接当成技术事实。
5. 冻结前保存来源列表、失败列表、片段总数、去重数量和文件哈希。

## 术语和关系的审核

概念包含稳定 ID、类型、俄英名称、可选中文说明、别名、定义证据和审核状态。关系类型至少包括 `broader_than`、`has_possible_cause`、`checked_by`；应明确方向以及适用的起点/终点类型。

词表中的同义词必须指向同一概念；相关但不等价的词不能当作同义词。诊断边表达可能性，不表达充分必要因果。

`data/ontology/seed.json` 当前为 `empty_scaffold`，概念和关系列表均为空，没有已审核知识。后续新增诊断关系应先标记为 `draft_unverified`；必须核实并填充证据后才能转为 `verified`。正式索引只接受符合结构约束、证据非空且审核状态通过的边。无证据的样例不能进入论文结论。
