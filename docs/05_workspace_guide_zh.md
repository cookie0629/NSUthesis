# 目录使用约定

## 1. 文件归属

所有项目产物保存在 `F:\thesis`。暂不改动其他项目，也不复用外部项目的虚拟环境。

| 路径 | 内容 | 注意事项 |
| --- | --- | --- |
| `docs/` | 研究计划、实验与语料规则、决策、进度 | `project_status.md` 是当前进度入口，已完成与计划分开 |
| `references/school/` | 学校任务书、报告模板、格式和时间要求 | 保存原件，记录适用版本；缺失的要求不可自行编造 |
| `references/literature/` | 允许保存的文献原文与元数据 | 书目不等于语料，不自动导入全文 |
| `references/notes/` | 方法、几何和文献阅读笔记 | 写清来源、方法、局限和与课题的关系 |
| `references/bibliography.bib` | 已核实文献的统一书目 | 未核实的候选先记在笔记中，不编造 DOI、页码 |
| `src/nurbs_knowledge/` | 可复用的 Python 正式实现 | 数据路径和参数不硬编码在模块中 |
| `scripts/` | 数据导入、实验执行、检查入口 | 业务逻辑放 `src/`；注明从项目根目录运行 |
| `configs/` | 语料切分、模型、检索和实验配置 | 开发配置与冻结配置必须标清状态 |
| `tests/` | 数据验证、检索和指标的实质性检查 | 空骨架目前不代表测试通过 |
| `data/sources/` | 来源与许可登记 | `pending` 不能进入正式索引 |
| `data/raw/` | 获准获取的原始网页、PDF、文本 | 保留原文；与来源 ID 对应；默认不纳入 Git |
| `data/interim/` | 清洗和抽取的中间文件 | 可重建，保留与原始资料的映射 |
| `data/processed/` | 正式片段、语料清单和快照元数据 | 片段保留来源、定位、版本、哈希 |
| `data/indexes/` | 本地关键词和向量索引 | 可重建，不与源代码混放 |
| `data/ontology/` | 术语、同义词与类型化关系 | 草稿与已核实状态分开，无证据关系不入正式索引 |
| `data/evaluation/` | 开发问题及其说明 | 独立测试题由评估负责人另行保管，不在开发阶段随意读取 |
| `experiments/protocols/` | 冻结协议、参数和数据哈希清单 | 冻结前仍为草稿，不能倒填冻结日期 |
| `experiments/runs/` | 每次实验的配置、原始结果、标签、指标和日志 | 按独立 `run_id` 保存，不覆盖旧结果 |
| `experiments/figures/` | 从真实运行生成的图表 | 记录输入 run_id 和生成命令 |
| `thesis/chapters/` | 俄文章节正文与提纲 | 未有证据的结果保留待写，不填写假数值 |
| `thesis/assets/` | 正文引用的图、表和示意图 | 记录数据或素材来源；示意图需标为示意 |
| `thesis/exports/` | 按学校模板导出的论文版本 | 正文源文件仍留在 chapters |
| `reports/weekly/` | 周报 | 每周记录产物路径、验证、结果、问题、下一步 |
| `reports/stages/` | 阶段报告、简短汇报讲稿 | 与学校阶段任务对应，注明草稿或已提交 |
| `reports/slides/` | 幻灯片源文件与导出 | 写明对应报告日期；目前尚无演示文稿 |
| `reports/demos/` | 演示输入、命令、输出和截图 | 必须来自真实演示，附环境和版本 |
| `reports/templates/` | 可复用周报与阶段报告结构 | 模板不等于已完成报告 |

## 2. 代码模块边界

`src/nurbs_knowledge/` 已建立可导入的空包，尚无业务功能。后续按下列职责实现：

| 模块 | 职责 |
| --- | --- |
| `ingest` | 来源登记、许可状态检查、原文抽取 |
| `chunk` | 结构化切分、片段 ID、定位与哈希 |
| `index` | BM25 和多语言向量索引 |
| `retrieve` | 基础检索、混合排序、受控术语扩展与一跳关系回取 |
| `evaluate` | 候选池、标注验证、统一指标与复现记录 |
| `answer` | 基于检索证据的引用回答，属于后续辅助层 |

先完成来源和片段验证，再实现 BM25。依赖版本、命令接口、嵌入模型须在实际验证后决定；本次没有提前固定未测试的工具组合。

## 3. 命名、版本与证据

- 代码、配置和数据文件名用小写英文和下划线；说明文档可用 `_zh`、`_ru` 标识语言。
- 周报用 `YYYY-MM-DD_weekly_zh.md`；阶段材料用 `YYYY-MM-DD_topic_ru.md`。文首注明“草稿 / 待审核 / 已提交”，没有提交记录不能写已提交。
- 来源、片段、概念、问题使用稳定 ID；具体格式在首轮数据校验实现时统一，不用数组位置充当 ID。
- 实验目录建议用 `YYYYMMDD_HHMMSS_<label>`，运行记录包含带时区的时间戳。所需字段见 `03_evaluation_protocol_zh.md`。
- 尚未初始化 Git；`.gitignore` 已预置。即使后续启用 Git，正式运行也要保存数据与配置 SHA-256，不能只记录代码提交号。
- 不删除或覆盖原始研究证据；修正数据和方法时保留旧版本并记录理由。测试污染后不能继续声称原测试集独立。

## 4. 每次工作结束时

1. 将产物放入对应目录，注明真实状态和证据来源。
2. 更新 `docs/project_status.md`；改变范围或协议时同步更新 `docs/decisions.md`。
3. 在当周周报写出产物路径、验证命令或审核方式，以及实际结果。
4. 将可解释的方法和结论写入相应章节；将适合汇报的内容写入阶段草稿。

当前无需安装数据库、模型或文档排版工具。正式报告采用何种文件格式，以学校模板为准。
