# 检索实验规范 v0.1

状态：预定协议，尚未开展实验。指标和参数在开发集上确认后冻结，冻结记录包含日期及文件哈希。

## 1. 对照组

| ID | 配置 | 要回答的问题 |
| --- | --- | --- |
| K | BM25 | 精确术语和 API 名称的基础效果 |
| V | 多语言向量检索 | 语义检索的基础效果 |
| H | K 与 V 的混合排序 | 后续增强方法的共同基线 |
| H+T | H 加术语扩展 | 同义词及选定上下位词扩展的增益 |
| H+R | H 加类型化关系检索 | 独立诊断关系的增益 |
| H+T+R | H 加两种增强 | 二者组合是否互补或引入噪声 |

T 不遍历诊断关系；R 允许概念链接所必需的别名识别，但不把这些别名另行作为同义词查询扩展。R 根据原查询链接概念并沿允许的类型化关系找证据。组合组默认也从原查询链接概念，避免隐式增加另一种扩展。所有组共用原文规范化和基础分词规则。

同一语料、切分、嵌入模型、相似度设置、最终返回数和去重规则适用于所有组。扩展项上限、关系跳数、融合权重、候选预算都必须记录；在开发集选择后保持固定。统一总候选预算，例如每次查询最多 100 个待融合候选，扩展查询和关系回取共同分配此预算。另记录实际计算次数和延迟，不能声称预算一致就意味着计算成本一致。

首轮不加入重排序器。如果后续加入，必须对比较的系统一致使用，并单独报告。

## 2. 问题集与隔离

最低 40 个问题，开发 10、测试 30；目标 60 个，开发 15、测试 45。按五类问题分层：定义/API、表示与参数、拟合、边界/连续性、容差/有效性。测试 30 个时尽量每类 6 个，不做过强的类别结论。

问题来自可追溯的真实任务或人工设计场景。人工设计的题必须标记为合成问题。不同语言翻译、改写和同一故障案例的变体作为同一家族，整体划入同一集合。不要直接从本体边反写所有测试问题，否则会夸大关系方法的优势。

允许系统使用全部已冻结检索语料；这是闭集语料检索，不是训练/测试文档分类。禁止依据测试问题、标准答案或测试排序错误继续补充本体和调参。测试题由评估负责人另行保管；若同一人承担开发与评估，应披露这一限制，冻结时间戳可辅助约束但不等同于完全盲测。

项目内 `data/evaluation/dev_questions.jsonl` 当前为空，后续只存放开发问题，无测试独立性。不得把开发样例的演示效果当成正式实验。

## 3. 相关性标注

标注单元为去重后的证据片段。每条记录包含 `query_id, chunk_id, grade, rationale, annotator, reviewed_at`。

等级：2 = 直接提供完成任务所需的关键证据；1 = 有帮助但不充分的背景或局部信息；0 = 不相关或无法支持本题任务。为每题预先写出证据需求，不以某个系统生成的答案作为判据。

冻结系统后，合并六组各前 10 条结果，加上独立人工搜索发现的相关片段，去重并打乱顺序。标注者不看片段来自哪个系统。所有系统前 10 条必须得到标注；未标注条目不能自动当作已确认不相关。

推荐抽取至少 20% 的查询池由第二位具有相关基础的人员复核，保存分歧及裁决；如无法获得第二标注者，如实说明单人判断和可能偏差。不伪造专家身份、一致性分数或审核过程。助手可预标注，但正式标签须人工核验并记录协助方式。

## 4. 指标

主指标：**nDCG@10**，以 `gain = 2^grade - 1` 衡量分级相关性与排序位置。

辅助指标：**MRR@10**（首个 grade=2 的倒数排名；无则为 0）、**Success@5**（前五条是否至少有一个 grade=2）、**已标注池 Recall@10**（将 grade>=1 视为相关，分母为池内全部已知相关片段）。池化 Recall 不能写成全语料真实召回率。

没有已知相关证据的问题应在冻结查询集前识别并单列。无答案问题可用于展示回答层拒绝臆测的能力，不混入主检索指标均值。正式池化后发现某题仍无已知相关证据，按预先规则单列并公开数量、原因及处理方式，禁止根据方法输赢选择性排除。

效率记录：每个查询的完整检索时间、编码时间、扩展候选数和调用成本；同一设备与缓存策略，记录是否包含查询嵌入。按统一预热方式重复三次，报告中位数；网络 API 延迟的波动单独说明。

报告逐问题指标、宏平均、按问题类别统计及配对差值。可按查询家族进行 bootstrap 得到 95% 区间，固定随机种子；样本小且来自特定语料，区间不表示可推广到所有 CAD 任务。主比较是 H+T+R 对 H，其余对照作为预先列出的机制分析，避免择优报告。

## 5. 回答层的辅助检查

检索实验完成后，选取预先规定数量的案例，例如每类 2 个，共 10 个。固定 LLM、提示词、温度、证据条数和上下文预算，人工检查引用是否支持断言、回答是否满足证据需求、证据不足时是否说明不确定。

这部分是辅助案例分析，不能替代检索指标。若用模型评分，应披露模型、提示词和局限；不能仅凭自评分认定正确。

## 6. 复现记录

每次运行至少保存：

- `run_id`、时间、代码版本或文件快照哈希、随机种子、依赖版本和硬件。
- 语料、切分、本体、查询和标注文件的版本及 SHA-256。
- 各组参数，包括分词、嵌入模型精确标识与版本、归一化方式、融合参数、扩展规则及预算。
- 每个查询的原文本、实际扩展项、概念链接、关系路径、片段 ID、得分、排名、耗时和错误。
- 原始运行文件、人工标签、汇总指标与图表生成方式。

结果表只在真实运行后填写。当前没有任何提升百分比、实验图或检验结果。
