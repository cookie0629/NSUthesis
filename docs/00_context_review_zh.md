## 2. 沿用的前置条件

- 用户本次确认：任务范围为现有文档中的 2026 年 9—12 月阶段项目。
- 研究知识检索支持工具；按既有决策，不额外开发曲面重建算法。
- 学生有 Python、OpenCascade 和几何算法实习基础；不从通用编程入门开始。
- 默认俄语查询、俄英语料；正式写作暂按俄文，项目指导和学习笔记用中文。
- 计划每周 15 小时，设备记录为 64 GB 内存；显卡能力尚无实测。
- 主检索实验本地运行，不依赖付费 API。若后续有必要调用 API，遵守总预算约 50 元、预留至少 10 元的规则。
- 六组实验为 K、V、H、H+T、H+R、H+T+R；增强方法共用混合检索基线。
- 允许负面结果；模型生成内容、开发演示和未核实关系不能充当正式研究证据。

## 3. 发现的缺口及处理

| 发现 | 本次处理 | 仍需做什么 |
| --- | --- | --- |
| 原 README 链接到不存在的 `seed.json` 和 `dev_questions.jsonl`；多处称已有数据样例 | 建立空数据容器，明确没有有效概念、关系和问题 | 根据实际来源整理并审核内容 |
| 研究计划要求确认几何算法边界，决策记录已写导师接受检索范围 | 沿用后者，修正文档间表述 | 若导师以后改变要求，再记录变更 |
| 决策记录把学校模板、篇幅、语言和引文格式列为“已确认”，但没有具体内容或附件 | 保留原有确认记录，标明执行细节尚无文件依据 | 将具体要求和原始模板放入 `references/school/` |
| 用户称“上学期”，原计划日期为 2026 年 9—12 月 | 用户本次明确就是这一阶段，已写入决策记录 | 最近汇报日期和最终论文期限仍无具体记录 |
| 原记录的状态标题为空，预算条目有笔误 | 修正标题与笔误，新增目录决定 | 持续记录研究或交付变更 |

## 4. 论文与汇报的关系

论文以“来源 → 数据 → 实现 → 实验 → 结论”形成证据链。周报每周说明实际产物、验证方式和下一步；阶段汇报从这些记录选取内容，解释研究目标、方法和阶段结果。

在没有系统和实验时，可以汇报研究设计、目录组织和实验协议；不能展示虚构的系统界面、运行截图或效果提升。本次汇报稿只覆盖真实完成的前期准备。
